## 6. L'Infrastructure de Contexte : L'Archiviste

**Changement principal par rapport à la v3 :** L'Archiviste n'est pas un agent éditorial. C'est un composant technique : il ne rédige rien, il ne juge rien, il récupère et assemble le contexte que les agents du §7 vont ensuite utiliser.

### Pourquoi ce composant existe

Au-delà d'une cinquantaine à une centaine d'atomes, préparer manuellement le contexte d'une requête (Story Bible + charte + glossaire + atomes liés) devient plus long que la tâche elle-même. C'est le point de friction identifié : le Niveau 1 (copier-coller) fonctionne bien tant que le dépôt est petit, mal au-delà.

### Quand le construire — pas avant

Ne construisez pas l'Archiviste en semaine 1. Construisez-le quand **au moins un** de ces critères est atteint :

| Critère | Seuil | Comment le mesurer |
|---------|-------|-------------------|
| Temps de préparation du contexte | > 10 minutes par requête | Chronométrez-vous pendant 1 semaine |
| Nombre d'atomes | > 80 atomes | `find 10_Atoms -name "*.md" | wc -l` |
| Oublis d'atomes pertinents | > 2 doublons créés par mois | Revue hebdomadaire avec l'Agent Contrôleur Qualité |

**Avant ce seuil, le Niveau 1 manuel (§9) reste plus rapide à utiliser qu'à automatiser.** C'est un principe d'ingénierie ordinaire : ne pas construire l'infrastructure avant d'en avoir la charge.

### Ce qu'il fait, une fois construit

Un script simple (`99_Agents/archiviste.py`), pas un service complexe :

1. **Parse** le frontmatter YAML de tous les atomes (`code`, `type`, `helix`, `status`, `tags`) et le corps du texte.
2. **Indexe** ce contenu (embeddings locaux ou API, stockage vectoriel léger type ChromaDB).
3. **Retourne** les N atomes sémantiquement les plus proches d'une requête libre, plus leurs liens directs `[[ ]]` à un saut de distance.
4. **Assemble** un bloc de contexte minimal (Story Bible + charte si la requête concerne un `N-` + atomes retrouvés), prêt à coller en tête du prompt destiné à l'un des agents du §7.

**Exemple de requête :**
```bash
python archiviste.py "je veux écrire sur la fatigue des SSM dans un contexte naval"
```

**Sortie attendue :**
```markdown
## Contexte assemblé

### Story Bible (extraits pertinents)
- GAN-14 opère en Méditerranée occidentale, 2042
- Matériel canonique : Rafale M, Frégates FDA, sous-marins nucléaires d'attaque

### Charte Stylistique (extraits)
- Structure en 5 temps : Situation initiale → Élément perturbateur → Péripéties → Climax → Dénouement
- Ton : réaliste, technique, sans pathos

### Atomes pertinents (top 5)
1. C-Markov_Blanket_Isolation (score: 0.87)
2. P-Identity_Impermeability (score: 0.82)
3. L-Inhibitory_Attention_Deficit (score: 0.79)
4. N-Story_4_The_Last_Token (score: 0.75)
5. E-Jetson_Sleep_Cycle (score: 0.71)

### Liens directs
- C-Markov_Blanket_Isolation → [[illustrates]] → N-Story_4_The_Last_Token
- C-Markov_Blanket_Isolation → [[validates]] → P-Identity_Impermeability
- C-Markov_Blanket_Isolation → [[threatened_by]] → L-Inhibitory_Attention_Deficit
```

### Ce qu'il ne fait jamais

Il ne décide de rien, ne modifie aucun fichier, ne fusionne aucun atome. Il prépare ; vous et les agents éditoriaux décidez.

## 8. Le Cycle de Vie du Vocabulaire

Un seul dépôt. Le français reste dans l'Inbox et les discussions. Le dépôt public est en anglais.

### Le Glossaire d'Ontologie Vivante

- **Fichier maître :** `00_Meta/Ontology_FR_EN.md` (source de vérité, modifié uniquement après validation)
- **Fichier tampon :** `00_Meta/Ontology_Pending.md` (propositions en négociation)

### Le Cycle en 4 Étapes

| Étape | Qui | Action |
|-------|-----|--------|
| 1. Détection | Agent Lexicographe | Repère un terme FR non répertorié, crée une fiche dans `Ontology_Pending.md` |
| 2. Négociation | Vous | Validez, corrigez, ou demandez une recherche bibliographique |
| 3. Ratification | Agent Lexicographe | Déplace la ligne vers `Ontology_FR_EN.md`, assigne un code stable |
| 4. Propagation | Agent Lexicographe | Propose de mettre à jour rétroactivement les anciens fichiers |

### Format d'une fiche de proposition (dans `Ontology_Pending.md`)

```markdown
## Proposition #42
- **Terme FR détecté** : "Sommeil génératif"
- **Contexte** : Utilisé dans N-Story_4 et E-Jetson_Sleep_Cycle
- **Proposition EN** : "Generative Replay" (technique) OU "Consolidating Reverie" (littéraire)
- **Recommandation** : "Generative Replay" pour E- et A- ; "Consolidating Reverie" pour N- et C-
- **Statut** : ⏳ En attente de validation
```

## 9. Le Flux de Travail Quotidien

### Niveau 1 : Chat + Éditeur (Point de départ — pas de date de fin prévue)

| Étape | Qui | Action |
|-------|-----|--------|
| 1. Capture | Vous (en FR) | Écrivez votre idée en vrac dans le chat ou dans `00_Inbox/` |
| 2. Contexte | Vous | Rassemblez manuellement Story Bible + charte (si `N-`) + atomes pertinents que vous connaissez déjà |
| 3. Atomisation | Agent (l'IA) | Retourne des blocs Markdown en anglais : nom, contenu, liens, tags |
| 4. Validation | Vous | Lisez, ajustez un mot si la nuance anglaise ne convient pas, copiez dans votre éditeur |
| 5. Commit | Vous | `git add` + `git commit`. L'historique Git est votre trace de décision |

**Métriques de succès du Niveau 1 :**
- Vous produisez 3-5 atomes par semaine
- Vous passez < 10 minutes à préparer le contexte par requête
- Vous créez < 2 doublons par mois

**Ce niveau reste parfaitement viable tant que les critères du §6 ne sont pas atteints. Ne le remplacez pas par anticipation.**

---

### Niveau 2 : Archiviste + Script Python (Une fois les seuils du §6 atteints)

**Critères de passage :**
- Vous passez > 10 minutes à rassembler le contexte avant une requête, OU
- Le dépôt dépasse ~80 atomes, OU
- Vous oubliez régulièrement un atome pertinent et créez des doublons (> 2/mois)

**Flux de travail :**
1. Vous écrivez dans `00_Inbox/vrac.md` ou posez directement votre requête
2. `archiviste.py` récupère automatiquement les atomes, la Story Bible et, si pertinent, la charte stylistique
3. Le contexte assemblé est transmis à l'agent concerné (Botaniste, Tisserand, etc.)
4. Un script crée automatiquement les fichiers `.md` dans les bons sous-dossiers
5. Vous relisez et corrigez dans VS Code / Obsidian

**Métriques de succès du Niveau 2 :**
- Temps de préparation du contexte < 2 minutes
- Taux de doublons < 1/mois
- Vous produisez 5-10 atomes par semaine

---

### Niveau 3 : Obsidian + Plugins (Visualisation du graphe, plus tard)

**Critères de passage :**
- Vous avez > 150 atomes
- Vous voulez visualiser les connexions entre atomes
- Vous voulez exporter le graphe pour des présentations

**Flux de travail :**
- Le repo Git est ouvert dans Obsidian
- Plugin "Smart Connections" ou "Text Generator" pour l'assistance IA
- Le graphe visuel montre immédiatement les orphelins et les nœuds surchargés

**Métriques de succès du Niveau 3 :**
- Vous identifiez visuellement les atomes orphelins en < 5 secondes
- Vous exportez le graphe pour des présentations externes

## 12. Les 6 Règles d'Or

1. **Un seul dépôt, une seule vérité.** Le français reste dans l'Inbox. Le dépôt public est en anglais.
2. **Un atome = Une idée.** Si une note aborde deux sujets, scindez-la.
3. **L'outil ne doit pas devenir le projet.** Pas d'IHM custom. Chat + éditeur + Git — même l'Archiviste reste un script.
4. **Le décor se crée à la demande.** Pas de worldbuilding sans récit qui l'exige.
5. **La fiction est un outil de validation.** Si la nouvelle ne "tient pas" face aux principes, c'est que le principe est mal défini OU la fiction mal écrite. Les deux s'améliorent mutuellement.
6. **N'automatisez pas avant d'avoir mal.** L'infrastructure de contexte (§6) se construit quand le manuel devient douloureux, pas par anticipation.

## 15. Évaluation du Projet : Comment Savoir si Ça Marche ?

### Métriques quantitatives

| Métrique | Cible hebdomadaire | Cible mensuelle | Comment mesurer |
|----------|-------------------|-----------------|-----------------|
| Nombre d'atomes créés | 3-5 | 15-20 | `find 10_Atoms -name "*.md" -mtime -7 | wc -l` |
| Nombre de liens créés | 5-10 | 25-40 | `grep -r "\[\[" 10_Atoms | wc -l` |
| Nombre de doublons détectés | 0-1 | < 5 | Revue avec Agent Contrôleur Qualité |
| Temps de préparation du contexte | < 10 min | - | Chronométrage manuel |
| Nombre de nouvelles complétées | - | 1-2 | Comptage manuel |
| Nombre de MVP démarrés | - | 1 | Comptage manuel |

### Métriques qualitatives

**Tous les 3 mois, posez-vous ces questions :**

1. **Est-ce que je comprends mieux mon projet qu'il y a 3 mois ?**
   - Si oui → le Zettelkasten fonctionne
   - Si non → vous faites du worldbuilding procrastinateur

2. **Est-ce que je peux expliquer le projet à un nouveau venu en 15 minutes ?**
   - Si oui → la Story Bible et le Codex sont clairs
   - Si non → révisez la Story Bible

3. **Est-ce que j'ai des candidats motivés pour travailler sur les MVP ?**
   - Si oui → le modèle de recrutement fonctionne
   - Si non → révisez le pitch ou les "Briques Jouables"

4. **Est-ce que la fiction et la technique s'enrichissent mutuellement ?**
   - Si oui → la double hélice fonctionne
   - Si non → vous avez deux projets séparés, pas un projet intégré

### Signaux d'alerte

- **Vous passez plus de temps à organiser le Zettelkasten qu'à produire du contenu** → Simplifiez
- **Vous créez des atomes `W-` et `K-` sans nouvelle associée** → Worldbuilding procrastinateur
- **Vous avez > 20 atomes orphelins (sans liens)** → Le Tisserand ne travaille pas assez
- **Vous ne pouvez pas retrouver un atome créé il y a 2 semaines** → L'Archiviste est nécessaire
